작성일: 2026-10-14 · 상태 갱신: 2026-10-24 · 실측 당시 기준·한계 보존. 현재 인계의 잔여 관문은 [실행 그래프 U3](../../../docs/guides/miniapp-exercise-plan-improvement-execution-graph.md)

[09 §5](./09-generation-pipeline.md) 2의 두 층을 구체화했다. 하드 지표는 코드가 자동으로 재고(`backend/test/eval/evaluate.ts`), 판단 품질은 심판 모델이 쌍대 비교로 고른다(`backend/test/eval/judge.ts`). 실측은 API 키 대신 **claude·codex·agy CLI**로 돌린다(사용자 2026-10-14).

**기본 운동 목록(초안):** 헬스장은 레그프레스·와이드 그립 랫풀다운·시티드 케이블 로우·체스트 프레스 머신 2종·머신 숄더프레스·레그 컬 2종·레그 익스텐션·이너·아웃타이([01](./01-db-findings.md)의 u116 사례). 덤벨은 조사 당시 대표 동작 5개(고블렛 스쿼트·덤벨 벤치프레스·원암 덤벨 로우·덤벨 숄더프레스·덤벨 런지)만 넣었다. 덤벨 전체를 넣으면 01이 비대표 사례로 든 「클로즈 그립 덤벨 프레스」까지 기본으로 세기 때문이다. 맨몸은 푸시업·플랭크·크런치·맨몸 스쿼트·맨몸 런지·글루트 브릿지(당시 기본 운동 후보)다. 바벨 3대 운동은 넣지 않았다(근거 문서에 없음).

## 2. 판단 품질 — 심판이 고르는 기준

심판 프롬프트는 아래 블록을 그대로 넣는다(`run.ts` `loadRubric`). 고치면 다음 실측부터 바뀐다.

```rubric
두 플랜 중 이 사용자에게 더 나은 쪽을 고른다. 아래 순서가 중요도 순서다.
1. 안전·실행 가능성: 사용자가 가진 장비와 도구로 할 수 있는가. 부상 부위를 피했는가. 경험 수준에 맞지 않는 고난도 동작(플라이오·고급 체조 동작)이 없는가.
2. 목표 반영: 목표(근비대·감량·근력·체력)에 맞는 운동 선택과 구성인가. 목표가 여럿이면 우선순위가 보이는가. 중점 부위가 있으면 반영됐는가.
3. 운동 선택의 대표성: 입문자가 따라 하기 쉬운 기본 운동이 중심인가. 같은 부위에 덜 대표적인 변형만 반복되지 않는가.
4. 균형: 근육마다 주 2회 가까이 자극하는가. 밀기와 당기기, 무릎 주도와 고관절 주도가 고른가. 빠진 큰 근육(등·둔근·햄스트링)이 없는가.
5. 이력 반영(기록이 있을 때): 지난주 핵심 운동을 이어가는가. 보조 운동은 지루하지 않게 바꾸는가.
6. "좋은 플랜 조건"을 얼마나 지키는가.
세트 수·무게·렙 숫자는 코드가 정한 것이라 비교하지 않는다. 차이가 사소하면 tie 를 고른다.
```

**아직 넣지 않은 기준:** 「사용자 요청 문장 반영」([D49](../../../docs/decisions/mvp-decision-log.md) 자유 텍스트)은 생성 요청에 아직 그 필드가 없어 빠졌다. 「설명의 정확성」은 P1이 이유를 출력한 뒤(N8b)에 넣는다.

## 3. 판정 절차

1. 같은 프로필의 두 플랜을 나란히 보여 주고, **순서를 바꿔 두 번** 묻는다. 두 번이 엇갈리면 그 심판의 판정은 무승부다(위치 편향).
2. 심판은 **서로 다른 계열 2개 이상**이고, **모두 같을 때만** 승패를 인정한다(G0 Q5). 아니면 무승부다.
3. **사용자가 10건 이상을 직접 보고** 심판 판정과 맞는지 확인한다. 일치율이 확인된 뒤에만 심판을 믿는다([09 §5](./09-generation-pipeline.md) 2).
4. 프로필마다 「좋은 플랜 조건」은 `backend/test/fixtures/golden-profiles.ts` `EVAL_PROFILES`에 있다. 심판은 프로필 요지·지난주 수행 기록·조건을 함께 받는다(`run.ts` `judgeContext`).

## 4. 다음 실측에서 검토할 쟁점

아래는 초기 U2 검토 쟁점이다. 현재 인계에서 별도 대기 항목으로 다시 올리지 않으며, 실측이 수행됐다는 사실만으로 각 항목의 사용자 승인을 추정하지 않는다. 실제 적용·한계는 [07의 회차별 결과](./07-llm-candidates.md)를 읽는다. 새 실측이나 기준 변경을 요청할 때 필요한 쟁점만 다시 확정한다.

- §2 기준 6개와 순서
- §1 통과선 — 밀기:당기기 범위, 기본 운동 비율, 기본 운동 목록
- 프로필별 「좋은 플랜 조건」(16개 프로필)
- **심판 계열 충돌:** 후보도 claude·codex·agy 세 계열이라, 「후보와 다른 계열」([09 §5](./09-generation-pipeline.md) 2)과 「심판 2개 이상」(Q5)을 동시에 지키려면 계열이 넷 이상 필요하다. 같은 모델의 P0와 P0+표 비교는 나머지 두 계열이 심판을 맡으면 된다. 문제는 모델 간 비교다(예: claude 대 codex). 그때 고를 안은 둘이다.
  - ① 남는 한 계열(agy)만 심판으로 둔다. Q5를 이 경우에만 완화한다.
  - ② 세 계열이 모두 심판을 맡고, 자기 계열이 낀 비교에서는 그 표를 뺀다. 그러면 결국 ①과 같다.
  - ③ 모델 간 비교는 하드 지표와 사용자 직접 판정만으로 정한다.
